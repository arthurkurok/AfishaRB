# 08. Нативные мобильные приложения (iOS + Android)

> Требование: настоящая нативная разработка, не Flutter. iOS — Swift/SwiftUI, Android — Kotlin/Jetpack Compose. Задача — чтобы каждое приложение ощущалось «своим» на платформе: системные жесты, виджеты, Live Activities, Siri и App Actions, динамический шрифт, тёмная тема. Тогда это не обёртка над сайтом.

## 1. Общая стратегия «нативно, но без дублирования логики»

| Что общее | Как обеспечено |
|---|---|
| API-клиент и модели | Генерация из `packages/contract/openapi.json` (OpenAPI 3.1, экспортируется из zod-схем контракта): Swift — `swift-openapi-generator` (официальный от Apple), Kotlin — `openapi-generator` (kotlin + kotlinx.serialization + Ktor). Ручного маппинга DTO нет. |
| Дизайн-токены | `packages/design-tokens` (формат W3C DTCG) → Style Dictionary → `Tokens.swift` и `Tokens.kt` (цвета light/dark, типографика, радиусы, отступы, тайминги анимаций). |
| Строки ru/ba | `packages/i18n` (ICU MessageFormat) → `Localizable.xcstrings` и `values/strings.xml`, `values-ba/strings.xml`. Плюрализация по правилам CLDR. |
| Иллюстрации и маскот | Векторные исходники → SVG/PDF для iOS Asset Catalog, VectorDrawable для Android; анимации — Lottie JSON или Rive (один файл на обе платформы). |
| Бизнес-правила | Живут на сервере: ранжирование, слоты ИИ, статусы. Клиенты тонкие, но с офлайн-кэшем. |
| Сценарии UI-тестов | Maestro (YAML) — один сценарий прогоняется на обеих платформах. |

**Почему не KMP:** с кодогенерацией API и токенов объём общей клиентской логики небольшой. KMP добавил бы iOS-команде Kotlin-зависимость и усложнил отладку, а выигрыш был бы маленьким. Решение зафиксировано в ADR-008 и может быть пересмотрено, если логика на клиенте вырастет (например, офлайн-поиск).

## 2. Минимальные версии ОС

| Платформа | Минимум | Обоснование |
|---|---|---|
| iOS | 17.0 | Observation framework, современный SwiftUI, интерактивные виджеты, TipKit. Покрывает iPhone XS/XR и новее. |
| Android | 8.0 (API 26) | Около 97 % активных устройств в РФ, включая бюджетные смартфоны в районах. `targetSdk` — актуальное требование Google Play и RuStore на момент релиза. |

Приложения обязаны нормально работать на слабых устройствах: Android с 3 ГБ ОЗУ и iPhone XR — эталонные устройства для перф-тестов.

## 3. Архитектура приложений

### 3.1. iOS

```
AfishaApp/
  App/               точка входа, DI-контейнер (простой, без фреймворков), роутинг
  Features/
    Home/            «Сегодня», подборки, «зонтик курая»
    Search/          фильтры, результаты, карта, календарь
    EventDetail/     паспорт события, сеансы, билеты, площадка
    Assistant/       чат с Гидом (SSE-стриминг)
    Favorites/       избранное, подписки, напоминания
    Map/             карта событий
    Diary/           культурный дневник, достижения
    Profile/         язык, город, дети, Пушкинская карта, приватность
    Onboarding/
  Core/
    API/             сгенерированный клиент + middleware (auth, retry, ETag)
    Persistence/     GRDB (SQLite): офлайн-кэш событий, избранное, черновики
    DesignSystem/    токены, компоненты (EventCard, Chip, KuraiNavigator, StatusBadge…)
    Analytics/       обёртка над AppMetrica (отключаемая)
    Push/            APNs + маршрутизация диплинков
  Extensions/
    Widgets/         WidgetKit: «Сегодня рядом», «Моё следующее событие», «Подборка недели»
    LiveActivity/    ActivityKit: обратный отсчёт до начала + адрес + кнопка «Маршрут»
    Intents/         App Intents: «Куда сходить сегодня», «Мои билеты/события», Spotlight
    NotificationService/ rich push с картинкой события
```

- Архитектура экранов: SwiftUI + `@Observable` модели представления, однонаправленный поток данных. Без тяжёлых фреймворков вроде TCA — порог входа ниже.
- Навигация: `NavigationStack` с типизированными маршрутами. Диплинки `afisha://event/{id}` и Universal Links `https://<домен>/e/{id}`.
- Карта: MapLibre Native или Yandex MapKit (выбор по итогам [06-data.md](06-data.md) и [10-finance.md](10-finance.md)).
- Сеть: `URLSession` через сгенерированный клиент, HTTP-кэш + `ETag`, повторы с экспоненциальной задержкой, офлайн-баннер.

### 3.2. Android

```
app/
  feature/home, search, event, assistant, favorites, map, diary, profile, onboarding
  core/
    network/        сгенерированный Ktor-клиент + интерсепторы
    database/       Room: офлайн-кэш, избранное
    designsystem/   токены, Compose-компоненты
    analytics/      AppMetrica (отключаемая)
    push/           RuStore Push SDK + FCM (если доступен) + HMS (опционально)
  widget/           Glance: «Сегодня рядом», «Следующее событие»
  shortcuts/        App Shortcuts + App Actions (Google Assistant, если доступен)
```

- MVVM + UDF: `ViewModel` → `StateFlow<UiState>`, события через `Channel`. Hilt для DI, Navigation Compose с типобезопасными маршрутами.
- Material 3 (Expressive — где уместно) с собственной цветовой схемой из токенов. Dynamic Color **не используем** (бренд важнее), но тёмная тема обязательна.
- Фоновые задачи: WorkManager (обновление кэша избранного, локальные напоминания на случай недоступности push).
- Сборка: Gradle version catalogs, baseline profiles для быстрого холодного старта, R8.

## 4. Функциональность приложений (сверх веба)

| Функция | iOS | Android | Зачем |
|---|---|---|---|
| Виджеты на рабочий стол | WidgetKit (S/M/L, интерактивная кнопка «В избранное») | Glance | Афиша «живёт» на экране без открытия приложения |
| Live Activity / Live Update в день события | ActivityKit: таймер до начала, адрес, «Маршрут» | Live Updates (progress-style notification) | Человек не опаздывает, событие ощущается «событием» |
| Голосовые сценарии | App Intents + Siri: «Куда сходить сегодня в Уфе» | App Actions / ярлыки | Быстрый вход в ассистента |
| Добавить в календарь | EventKit | CalendarContract intent | — |
| Поделиться карточкой | Share Sheet + сгенерированная картинка-превью (сторис 9:16) | Sharesheet | Вирусность: красивые карточки для сторис VK и Telegram |
| Офлайн | Избранное и сохранённые подборки доступны без сети | То же | Слабый интернет в районах |
| Напоминания | Push + локальные уведомления как резерв | То же | Push в РФ может работать нестабильно |
| Культурный дневник | Отметка «Я был» по геолокации рядом с площадкой (±300 м, в окне события) или по QR на площадке | То же | Геймификация, «Культурный итог года» |
| Доступность | VoiceOver, Dynamic Type до AX5, Reduce Motion, Smart Invert | TalkBack, масштаб шрифта 200 %, Remove animations | ГОСТ Р 52872 по духу, аудитория старшего возраста |
| Режим «Просто» | Крупные элементы, 3 кнопки: «Сегодня», «Рядом», «Позвонить в кассу» | То же | Пожилые пользователи |

## 5. Push-уведомления

| Тип | Триггер | Ограничения |
|---|---|---|
| Изменение события в избранном | `change_log`: перенос, отмена, распродано, смена площадки | Всегда, кроме тихих часов (кроме отмены в день события) |
| Напоминание | За день (18:00) и за 3 часа | Настраивается |
| Сохранённый поиск | Появились новые события по подписке | Не чаще 1 раза в день, дайджестом |
| Подборка недели | Четверг 18:00 (по TZ региона) | Только с явного согласия |
| Последний шанс | Выставка в избранном закрывается через 3 дня | Не чаще 1 раза на событие |

- Доставка: APNs (iOS); на Android — RuStore Push как основной канал, FCM как дополнительный, HMS — опционально. Сервер `notify` хранит несколько токенов на устройство и выбирает транспорт.
- Rich push с картинкой (Notification Service Extension на iOS, BigPicture на Android).
- Всё дублируется во «Входящие» внутри приложения. Если push не дошёл, человек всё равно увидит уведомление.
- Детали ограничений доставки в РФ и регистрации в магазинах — в [09-compliance-security.md](09-compliance-security.md).

## 6. Аутентификация

- Без входа доступно всё, кроме синхронизации между устройствами. Избранное хранится локально и привязывается к анонимному `device_id`.
- Вход (по желанию) — **только российские способы**, так требует ст. 8 149-ФЗ (авторизация российских пользователей — по номеру телефона, через ЕСИА, ЕБС или российские ИС): номер телефона (одноразовый код), VK ID, Яндекс ID, Госуслуги (ЕСИА) — на позднем этапе. Sign in with Apple, Google и Telegram Login как способы входа **не используются**. Для App Store это допустимо: правило 4.8 требует альтернативного входа только при наличии сторонних соцлогинов, а собственная учётная система по телефону и госидентификация (ЕСИА) под него подпадают. Это нужно перепроверить по актуальной редакции App Review Guidelines перед подачей.
- Связка Telegram-бота с аккаунтом — одноразовым кодом из приложения или сайта, а не входом через мессенджер.
- При входе анонимное избранное сливается с аккаунтом.
- Токены: короткий access JWT + refresh в Keychain / EncryptedSharedPreferences (или DataStore + Tink).

## 8. Публикация

- Каналы: App Store, RuStore (основной для Android в РФ), Google Play, AppGallery, прямой APK на сайте как резерв.
- Подготовка к ревью: политика конфиденциальности, App Privacy labels, Data safety, описание рекомендательной системы, демо-аккаунт не нужен (вход опционален).
- Риски 2026 года (удаления приложений из App Store по требованиям РКН, сложности с оплатой Developer Program, обязательная предустановка RuStore) и решения — в [09-compliance-security.md](09-compliance-security.md) §5. Аккаунты магазинов — на министерство или подведомственное учреждение ([13-owner-tasks.md](13-owner-tasks.md), блок Г).
- **На хакатоне** магазины не нужны: iOS — симулятор и бесплатная подпись на своё устройство, Android — APK. Приложения разрабатываются с 02.11 параллельно с бэкендом (11-roadmap, фаза П), офлайн-кэш — с первых экранов: при отключениях мобильного интернета в районах РБ продолжают работать только офлайн-кэш приложений и уже загруженные данные.
- Корень НУЦ Минцифры встроен в доверенные сертификаты приложения (09 §4), так что приложения не зависят от внешних УЦ.
- Фичефлаги с сервера (`/app/config`): включение ИИ и новых экранов без выпуска обновления. Принудительное обновление при несовместимости API.
