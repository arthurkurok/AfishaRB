# 14. Защита: история, демо, ответы на вопросы

> Защита 15.11.2026 в формате «презентация кода и аргументация решения». Оценивает заказчик — Министерство культуры РБ. Хронометраж уточнить на открытии; ниже — версия на 7 минут + вопросы.

## 1. Главная мысль

**«Афиша, которой можно верить. Для всей республики. Даже без интернета в районе.»**

Три доказательства, которые жюри должно увидеть своими глазами:
1. **Ноль выдуманных событий:** Гид на провокациях + паспорт события с источником и временем проверки.
2. **Вся республика:** события сёл и районов, бесплатные, по Пушкинской карте, на башкирском.
3. **Инструмент министерства:** отмена в кабинете → уведомление за секунды; «Пульс культуры» показывает спрос без предложения.

## 3. Слайды (не больше 10)

1. Обложка: название, маскот, команда.
2. Проблема: цифры (8,5 тыс. событий, 88 % вне крупных городов, 17 % освоения Пушкинской карты, пример с Дублином).
3. Решение: каналы одной схемой.
4. Чем мы отличаемся: таблица «типовое решение / Афиша.ру с ГигаЧатом / мы» — 6 строк (достоверность, сёла, статусы, двуязычие ru/ba, API и виджет, аналитика министерства).
5. Как устроена достоверность: схема «LLM не источник фактов» (05 §1).
6. Архитектура: схема контейнеров (04 §3).
7. Законы и безопасность: таблица соответствия (09 §1, 6 ключевых строк).
8. Экономика: стоимость владения против эффекта (10 §3.4 и §4).
9. План внедрения: пилот → республика → тиражирование (11, фаза Р).
10. Контакты + QR на живой стенд, бота и API.

## 4. Код на защите («презентация кода»)

Подготовить три коротких фрагмента (по 30 секунд):
- **Верификатор фактов** (`assistant/verifier`) — как ни одна цифра из LLM не попадает к пользователю без проверки.
- **Правила выживания полей и provenance** (`dedup`/`catalog`) — почему карточке можно верить.
- **Zod-схемы `packages/contract` → OpenAPI 3.1 → сгенерированные клиенты Swift и Kotlin** — нативность без дублирования; сайт, виджет и админка используют те же схемы напрямую.

Плюс открытый `jury/reports/` — «мы сами себя проверяли десятью экспертами-агентами»: отчёты и исправленные замечания.

## 5. Вопросы, которые зададут, и ответы

| Вопрос | Ответ |
|---|---|
| Откуда данные и почему им верить? | PRO.Культура (официальный источник учреждений) + открытые данные Минкультуры + kulturarb + кабинет учреждения. У каждого поля — источник и время проверки. Извлечённое ИИ без модерации не публикуется |
| Чем вы лучше Афиши.ру с ГигаЧатом? | Они продают билеты в 17 городах. Мы показываем всю республику, включая бесплатное и сельское. Мы показываем статусы и источники, у нас есть открытый API и виджет, кабинет учреждений и аналитика для министерства |
| Что будет, если GigaChat упадёт? | Поиск и фильтры работают без ИИ; Гид переходит на разбор запроса правилами — покажем вживую, выключив ключ |
| Telegram же заблокирован и 41-ФЗ? | Telegram-бот сделан по ТЗ: Bot API — через исходящий прокси, данные пользователей — в РФ. По 41-ФЗ рекомендуем: оператор бота — не госорган и не подведомственное учреждение (подрядчик или партнёр) или бот без персональных рассылок; решение — за юристами министерства. Те же функции есть на сайте и в приложениях: ядро диалога одно для всех каналов |
| Как вы узнаёте об отменах? | В федеральном API статусов нет. Источники: кабинет учреждения, билетные системы, детектор исчезновений, модерируемые сигналы VK. Предлагаем министерству регламент «отмена — в течение 2 часов» |
| Персональные данные? | Пользоваться можно без регистрации. Данные — в РФ. ПДн маскируются до отправки в GigaChat. Вход — только российскими способами (ст. 8 149-ФЗ) |
| Сколько стоит содержать? | «Железо» + ИИ — около 1,6–1,9 млн ₽ в год при 100 тыс. MAU. Маршрутизация моделей снижает расходы на ИИ в 5 раз |
| Кто будет наполнять? | Учреждения уже вносят события в PRO.Культура — мы их забираем. Кабинет с ИИ-помощником экономит ~10 минут на событие. Бесплатный виджет для сайта учреждения мотивирует держать данные актуальными |
| Почему нативные приложения, а не PWA? | Офлайн при отключениях мобильного интернета, виджеты и Live Activity, push, RuStore. PWA и Mini App тоже есть |
| Башкирский язык? | Интерфейс на двух языках (перевод выполнила команда с помощью ИИ, самопроверка по словарям и корпусу Bashkorttele; после запуска приглашаем носителей к правкам), Гид понимает запросы на башкирском, двойные топонимы. Качество ответов на башкирском измеряем отдельным eval |
| Госсимволика в дизайне? | Не используем. Курай — как зонтик-соцветие, без семилепесткового цветка в круге (Закон РБ № 10-з) |

## 6. Подстраховка

- Демо-стенд в облаке + локальная копия в docker-compose на ноутбуке.
- Резервное видео всех пяти демо (записано 14.11).
- Демо-запросы прогреты в кэше; второй провайдер GigaChat настроен.
- Два телефона: iOS и Android, Telegram залогинен (VPN проверен), яркость на максимум, «Не беспокоить» включён.
