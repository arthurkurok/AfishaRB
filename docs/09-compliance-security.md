> Состояние законодательства на 02.11.2026. Это инженерная карта требований, а не юридическое заключение. Пункты с пометкой «⚖️» нужно подтвердить у юриста министерства до промышленного запуска.

## 2. Персональные данные

### 2.1. Что мы храним

| Данные | Объём | Основание | Срок |
|---|---|---|---|
| Анонимный `device_id`, избранное без аккаунта | Все пользователи приложений | Исполнение функции по запросу пользователя | Пока установлено приложение |
| Аккаунт: телефон или ID VK/Яндекса, имя (опционально) | Только зарегистрированные | Согласие (отдельное) | До удаления аккаунта |
| Предпочтения: город, возраст детей, интересы | По желанию | Согласие | До удаления |
| ID в Telegram, состояние диалога | Пользователи бота | Согласие при `/start` (кнопка) | 12 месяцев неактивности → удаление |
| Push-токены | С согласия на уведомления | Согласие | До отзыва |
| Геопозиция | Только в момент запроса, не хранится | Согласие ОС | Не хранится |
| Логи ИИ (`AssistantTrace`) | Все диалоги, **после маскирования ПДн** | Обезличенные данные | 90 дней |
| Агрегаты поиска для дашборда | Обезличенно | — | Бессрочно |

ID в Telegram считаем ПДн (позиция РКН об идентификаторах; прямого разъяснения по Telegram нет).

### 2.2. Маскирование перед GigaChat

Перед отправкой в LLM текст проходит через маскировщик: телефоны, email, номера карт и документов, адреса с номером квартиры, ФИО по словарю и шаблонам → плейсхолдеры `[PHONE]`, `[EMAIL]`, `[NAME]`. В промпт не передаются ID пользователя, профиль и геопозиция — только вычисленные слоты (город, бюджет, возраст ребёнка).

### 2.3. Права субъекта

«Скачать мои данные» и «Удалить аккаунт» — в профиле; в боте — `/privacy`. Удаление — каскадное, в течение 30 дней из бэкапов.

## 3. Безопасность приложения

| Область | Меры |
|---|---|
| Аутентификация админки | Пароль (argon2id) + TOTP 2FA обязательно, блокировка после 5 попыток, сессии с привязкой к устройству, журнал входов |
| Авторизация | RBAC (03 §8) + **изоляция учреждений**: каждый запрос Admin API проверяет `organization_id` на уровне сервиса и RLS в Postgres |
| Входные данные | Валидация запросов и ответов zod-схемами контракта (Fastify), параметризованные запросы (Drizzle; сырой SQL — только через шаблон `sql` с параметрами), лимиты размера |
| Контент из источников | Санитизация HTML по allow-list (sanitize-html), CSP на сайте (`script-src 'self'` + nonce), экранирование в боте (Markdown/HTML-режимы Telegram) |
| SSRF в коннекторах | Allow-list доменов источников, запрет приватных диапазонов IP, таймауты, ограничение размера ответа |
| Rate limiting | Valkey token bucket: по IP, API-ключу, пользователю бота; отдельные лимиты на ИИ (10 запросов в минуту на пользователя) |
| Бот | Telegram — проверка `secret_token` вебхука (или long polling через прокси); Mini App — проверка подписи `initData` |
| ИИ | Тексты событий передаются как данные; у модели нет инструментов записи; верификатор; квоты; журнал |
| Секреты | Lockbox или Vault облака, ротация, никаких секретов в образах и мобильных сборках; ключ GigaChat только на сервере |
| Цепочка поставок | Lock-файлы (`pnpm-lock.yaml`), `pnpm audit` / trivy в CI, SBOM (CycloneDX), подпись образов (cosign), Renovate |
| Инфраструктура | Приватные подсети для БД и Valkey, WAF и защита от DDoS у провайдера, бэкапы с шифрованием, PITR, ежеквартальная проверка восстановления |
| Мониторинг ИБ | Алерты на всплески 401/403/429, аномальные выгрузки API, изменения ролей в админке |

## 4. TLS-сертификаты

- Let's Encrypt с июня 2026 не обслуживает российские госструктуры; GlobalSign отзывает сертификаты у подсанкционных организаций; DigiCert и Sectigo не работают с зоной `.ru`.
- Корневой сертификат НУЦ Минцифры бесплатен (через Госуслуги), но Chrome, Safari, Firefox и Edge ему не доверяют (Яндекс Браузер доверяет).
- **Схема:**
  - на время хакатона и пилота домен принадлежит команде (не госоргану) → Let's Encrypt;
  - в промышленной эксплуатации — публичный сертификат, если его удаётся получить для домена, + резервный сертификат НУЦ;
  - в нативных приложениях корень НУЦ встроен в доверенные сертификаты приложения, поэтому приложения не зависят от внешних УЦ.
- Исходящие соединения к GigaChat требуют корня НУЦ: он подключается клиенту GigaChat как кастомный CA, проверка TLS не отключается (05 §3.1).

## 6. Чек-лист до промышленного запуска

1. ⚖️ Статус системы (ГИС или иная ИС министерства), оператор ПДн, владелец аккаунтов магазинов и бота.
2. Уведомление РКН (новое или изменение действующего) с адресом БД в РФ.
3. Политика ПДн, три отдельных согласия, cookie-баннер (сайт); в виджете cookies нет.
4. Определён уровень защищённости (УЗ-4 или УЗ-3) и класс по № 117; модель угроз; аттестация, если система — ГИС.
5. Договор поручения обработки и условия использования данных с поставщиком GigaChat: данные не используются для обучения, настроены ограничения blacklist.
6. Опубликованы правила применения рекомендательных технологий.
7. ⚖️ Юридическая схема для Telegram-бота по 41-ФЗ.
8. Регламент «каталог — не реклама».
9. Аудит доступности по ПП 102 (сайт и виджет) и WCAG 2.2 AA (приложения).
10. Пентест (внешний) и устранение критичных находок.
11. План реагирования на инциденты, включая уведомление РКН об утечке (24 часа и 72 часа).
12. Бэкапы и проверенное восстановление (RPO 15 мин, RTO 4 ч).
