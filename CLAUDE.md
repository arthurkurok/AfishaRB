# Афиша культуры Башкортостана

Единая достоверная афиша культурных событий Республики Башкортостан для Минкультуры РБ: веб, Telegram-бот и Mini App, нативные iOS (Swift) и Android (Kotlin), открытый REST API, встраиваемый виджет, ИИ-гид на GigaChat. Это полноценный продукт к эксплуатации, а не MVP.

## План — источник истины

Перед задачей прочитай раздел плана, на который она ссылается. Если код и план расходятся, побеждает план, а отклонение оформляется ADR в `docs/adr/`.

- `docs/00-brief.md` — ТЗ и матрица трассировки требований: при спорах о скоупе.
- `docs/04-architecture.md` — модули, модель данных, API, SLO, ADR: при любом изменении бэкенда, схемы БД или API.
- `docs/05-ai-agent.md` — ИИ-гид: при работе с `assistant/`, промптами, `eval/`.
- `docs/06-data.md` — источники, дедупликация, статусы: при работе с `ingestion/`, `dedup/`, `lifecycle/`.
- `docs/07-design.md` — дизайн-система и голос бренда: при любом UI и любом пользовательском тексте.
- `docs/08-mobile.md` — iOS и Android.
- `docs/09-compliance-security.md` — ПДн, законы, безопасность: при работе с пользовательскими данными, аналитикой, уведомлениями.
- `docs/11-roadmap.md` — этапы M0–M7 и их задачи.
- `docs/12-dev-loop-jury.md` — процесс: цикл жюри, DoR/DoD, стратегия тестов.

## Стек

- Python в проекте не используется — только TypeScript (Node.js); для iOS — Swift, для Android — Kotlin.
- Бэкенд — `apps/api`: Node.js 24 LTS, TypeScript strict, Fastify 5 + zod, Drizzle ORM, pg-boss, grammY. Модули — `src/modules/<name>/`, точки входа — `src/main/{api,bot,worker}.ts`. Монорепозиторий на pnpm workspaces. Полный стек и обоснования — `docs/04-architecture.md` §4, §17 и ADR-014.

## Инварианты

1. **Достоверность.** Карточка события в любом канале строится из БД по ID. Текст LLM попадает к пользователю только через верификатор фактов (`apps/api/src/modules/assistant/verifier.ts`). Каждое поле события имеет provenance.
2. **Время.** Хранение в `timestamptz`. «Сегодня», «в субботу», «вечером» вычисляются в `Asia/Yekaterinburg` (UTC+5) — часовой пояс региона из конфигурации `region`, никогда не часовой пояс сервера.
3. **Contract-first.** Изменение API начинается с zod-схем в `packages/contract`. Из них экспортируется `openapi.json` (OpenAPI 3.1; CI проверяет дрейф) и генерируются клиенты Swift и Kotlin; web, widget и admin импортируют схемы и типы напрямую. Сгенерированный код не правится руками.
4. **Два языка.** Каждая новая строка интерфейса добавляется в `packages/i18n` сразу на `ru` и `ba`. Если перевода на `ba` ещё нет, ключ помечается `needs_translation` — это видно в отчёте `jury-a11y`.
5. **Дизайн-система.** В UI — только токены из `packages/design-tokens` и компоненты библиотеки. Цвета, размеры и тайминги вне токенов — нарушение.
6. **GigaChat — только через AI Gateway** (`apps/api/src/modules/assistant/gateway`): бюджеты, кэш, семафор параллельности, обработка `blacklist`/429/402, маскирование ПДн. Другие модули вызывают GigaChat только через публичный сервис Gateway; HTTP-клиенты GigaChat (undici/fetch, `openai`) живут только внутри `gateway`.
7. **Регион.** В каждой доменной таблице есть `region_id`. Регионально-специфичное (муниципалитеты, языки, часовой пояс, бренд) живёт в данных, а не в коде.
8. **Границы модулей.** Модуль в `apps/api/src/modules/` обращается к другому только через его `index.ts` — публичный сервис и типы модуля; внутренние файлы модуля видны только ему самому. Правило проверяет `dependency-cruiser`.

## Как работать

- Сначала тест, который воспроизводит поведение (красный), затем код (зелёный).
- `make check` — одна команда для линтеров (Biome), типов (`tsc --noEmit`), границ модулей (dependency-cruiser), юнит- и интеграционных тестов (vitest на реальной Postgres из docker-compose, база `afisha_test`), контрактных и быстрых e2e-тестов (Playwright). Задача не готова, пока он не зелёный.
- Идентификаторы в коде — на английском. Комментарии, документация, тексты интерфейса и описания коммитов — на русском. Формат коммитов — Conventional Commits.
- Закончил этап — запусти workflow `jury-loop` с `{"milestone": "M<N>", "scope": "<что сделано>"}`. Гейт и рубрика описаны в `jury/RUBRIC.md`.
- Нужен доступ, ключ, решение министерства или ассет от человека — сверься с `docs/13-owner-tasks.md`. Если задачи там нет, добавь её и работай с моком до получения.
