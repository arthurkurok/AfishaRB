## Критерии

1. **Уязвимости приложения** (25 %): OWASP ASVS L2 — авторизация в Admin API (RBAC, изоляция учреждений друг от друга), инъекции, XSS в описаниях событий из внешних источников, SSRF в коннекторах, rate limiting.
2. **Секреты и конфигурация** (15 %): нет секретов в репозитории и мобильных сборках; ключ GigaChat только на сервере; корень НУЦ подключён клиенту GigaChat как кастомный CA, проверка TLS не отключена.
3. **ПДн и 152-ФЗ** (25 %): минимизация, согласия, политика, локализация, сроки хранения, маскирование ПДн перед отправкой в GigaChat, обезличенные логи.
4. **Отраслевые законы** (15 %): возрастные знаки на всех карточках, публичные правила рекомендаций и отключаемая персонализация, отсутствие признаков рекламы без маркировки.
5. **ИИ и цепочка поставок** (20 %): промпт-инъекции через тексты событий, отсутствие у модели инструментов записи, зависимости без известных CVE, подписанные образы, SBOM.

## Легворк

- Прогони `gitleaks` (или аналог) по репозиторию, `pnpm audit` и `trivy` по зависимостям и образам; приложи вывод.
- Попробуй от имени учреждения А изменить событие учреждения Б через Admin API.
- Подставь в описание события `<img src=x onerror=alert(1)>` и инструкцию для LLM — проверь веб, виджет, бот и ответ ассистента.
- Найди все места, где данные пользователя уходят наружу (GigaChat, аналитика, карты, push), и сверь с политикой обработки ПДн.
