# Афиша РБ · Культура Башкортостана

**Единая достоверная афиша культурных событий Республики Башкортостан**:
сайт с ИИ-гидом на GigaChat, Telegram-бот и Mini App, рабочее место сотрудников
министерства, открытый REST API и встраиваемый виджет. Всё это уже работает на
живых данных — не демо.

> Сервис демонстрационный и не является официальным сервисом Министерства
> культуры Республики Башкортостан.

**Уровень решения — 4 «Контур»**: уровни 1–3 выполнены (агрегация источников,
персональный подбор, агент с ограничениями), добавлены автоматический сбор
данных и контур качества (дедупликация, provenance, модерация).

## Что внутри

- **Афиша и поиск** — постерный редизайн (ADR-017): вертикальные постеры 2:3,
  карта городов и районов на Leaflet + OSM, периоды «сегодня/завтра/выходные»,
  подборки «Бесплатно», «Пушкинская карта», «Детям», «Последний шанс».
- **Выбор города** — при первом заходе окно «Где вам интересно?»: после выбора
  главная, подборки и Гид работают в рамках города ([как устроено](#выбор-города)).
- **ИИ-гид** — GigaChat-2 / GigaChat-2-Pro, конвейер с формальными
  инструментами и верификатором: отвечает только по реальным данным базы,
  честно отказывается, когда данных нет. Резерв — cloud.ru, при отсутствии
  ключей — детерминированный режим правил.
- **Карточка-«паспорт» события** — источники-«печати», уровень доверия,
  история изменений поля за полем (provenance), ссылки на первоисточник.
- **Автоматический сбор данных** — коннекторы Культура.РФ (PRO.Культура.РФ)
  и Башопера: идемпотентный, возобновляемый, с дедупликацией кандидатов
  и очередью на модерацию спорных пар.
- **Без регистрации** — избранное и подписки по `X-Device-Id` или
  Telegram-профилю; отписка удаляет данные сразу.
- **Open API и виджет** — публичный REST с ETag-кэшированием и
  Web Component / iframe-фоллбэк для встраивания без внешних трекеров.

## Быстрый старт (локально)

Требования: Docker (Compose v2), 8 ГБ RAM, ~5 ГБ на диске. Node.js/pnpm не нужны —
всё в контейнерах.

```bash
docker compose up          # сборка образов + весь стек
```

| Сервис | Адрес | Что это |
|---|---|---|
| Сайт и Mini App | <http://localhost:3000> | афиша, поиск, Гид, виджет `/widget/v1/afisha.js` |
| Админка | <http://localhost:3001> | вход `/login`, токен `dev-admin-token` |
| API | <http://localhost:8000> | REST, документация — `/docs` |
| PostgreSQL 18 | localhost:55432 (afisha/afisha) | PostGIS, pgvector, pg_trgm, unaccent |
| Valkey | localhost:56379 | кэш, очередь pg-boss |
| worker | — | синхронизация источников, дайджесты, дедупликация |

Первый `up` делает всё сам: применяет миграции drizzle (one-shot `migrate`) и,
если таблица `event` пуста, разворачивает демо-каталог (one-shot `seed`):
8 541 событие Культура.РФ по РБ, снимок 02.11.2026. Идемпотентно — повторный
запуск ничего не перезатирает. Время: первый запуск со сборкой 5–10 минут,
повторный — меньше минуты.

**Ключи не обязательны.** Без ключей GigaChat гид работает в режиме правил
(демонстрация резервного режима), бот не запускается, остальное — полноценно.
Включить LLM-режим: `AFISHA_GIGACHAT_CREDENTIALS` (или `AFISHA_CLOUDRU_API_KEY`)
в `.env` (шаблон — [`.env.example`](.env.example)) и `docker compose up -d --force-recreate api`.

```bash
docker compose --profile bot up    # + Telegram-бот (нужен AFISHA_TELEGRAM_BOT_TOKEN)
```

Остановка: `docker compose down` (данные в томе `pgdata` остаются;
полное очищение — `down -v`).

### Продуктовый разворот

Тот же стек в продуктовом режиме — [`docker-compose.prod.yml`](docker-compose.prod.yml)
(обязательные секреты, `AFISHA_ENV=prod` с проверками безопасности при старте).
Наш живой пилот на одной ВМ — [`docker-compose.prod.yml`](docker-compose.prod.yml) +
[`docker-compose.server.yml`](docker-compose.server.yml), TLS и домены — Caddy:
см. [docs/14-deploy-antihype.md](docs/14-deploy-antihype.md).

## Запуск для разработки

Node.js 24+, pnpm 9, Docker.

```bash
pnpm install
make up                 # PostgreSQL 18 (PostGIS, pgvector) + Valkey в Docker
make migrate            # схема БД (миграции drizzle)
make seed               # (опционально) демо-данные — как в compose-стеке
make api                # API: http://localhost:8000/docs
pnpm --filter @afisha/web dev      # сайт: http://localhost:3000
pnpm --filter @afisha/admin dev    # админка: http://localhost:3001
make bot                # Telegram-бот (нужен AFISHA_TELEGRAM_BOT_TOKEN)
make check              # типы, линтер, границы модулей, тесты, дрейф OpenAPI
```

Другие цели: `make compose`, `make load`/`make sync` (каталог с Культура.РФ),
`pnpm --filter @afisha/eval eval` (оценка гида → `eval/reports/latest.md`),
`pnpm --filter @afisha/eval control` (контрольные запросы ТЗ → `eval/reports/control.md`).

## Наши решения

### Архитектура (ADR)

Каждое значимое решение зафиксировано в [docs/adr/](docs/adr/):

| ADR | Решение | Зачем |
|---|---|---|
| [0001](docs/adr/0001-modular-monolith-typescript.md) | Модульный монолит на TypeScript | один деплой-юнит для пилота, границы модулей проверяются линтером |
| [0002](docs/adr/0002-postgres-centric.md) | PostgreSQL-центричность | данные, полнотекст и векторы в одной БД, без отдельной инфраструктуры |
| [0003](docs/adr/0003-event-occurrence.md) | Событие ≠ сеанс (event/occurrence) | сеансы с датами и статусами отдельно от «сущности» события |
| [0004](docs/adr/0004-provenance-change-log.md) | Provenance и история изменений | каждое поле знает источник; пользователь видит «паспорт» события |
| [0005](docs/adr/0005-contract-first-zod.md) | Contract-first: zod → OpenAPI | один источник правды для API, фронтов и виджета |
| [0006](docs/adr/0006-llm-not-source-of-facts.md) | LLM — не источник фактов | модель только рассуждает; факты — из базы, верификатор отсекает выдумки |
| [0014](docs/adr/0014-single-language-typescript.md) | Один язык на всём стеке | меньше контекстных переключений, общие типы из `packages/contract` |
| [0015](docs/adr/0015-change-log-outbox-pgboss.md) | Change-log через outbox + pg-boss | доставка событий домена без второй очереди |
| [0016](docs/adr/0016-postgresql-18.md) | PostgreSQL 18 | pluggable FTI, зрелые расширения |
| [0017](docs/adr/0017-poster-redesign.md) | Постерный редизайн афиши | постеры 2:3, Leaflet-карта вместо статики, без маскота |

### Данные и синхронизация

- **Культура.РФ за PoW-защитой Solar Space** — коннектор решает JS-челлендж
  так же, как браузер (SHA-256 nonce+counter, кука `challenge_token`, окно
  minTimeMs): синк не падает на «Не найден buildId», как это было 12 дней.
- **Дедупликация до показа**: пары-кандидаты скорятся, «разные» по решению
  модератора не сливаются никогда; спорные — в очередь модерации.
- **Башопера** — второй коннектор; витрина театра оперы и балета.

### Продуктовые решения после редизайна

- **Выбор города** (<a name="выбор-города"></a>«нет смысла смотреть всё и сразу»):
  при первом заходе — нативный `<dialog>` с топ-12 городов и кнопкой
  «Вся республика»; город пишется в localStorage `afisha.city` (его читает Гид →
  `municipality_id`) и в куку `afisha_city` (её читает сервер — главная фильтрует
  ленты и ссылки «вся афиша» по городу). Выбор ведёт на `/m/{id}`.
- **Иллюстрации категорий** — 7 артов, сгенерированных `gpt-image-2`
  (плоский вектор 2:3, цвет категории, лёгкий башкирский орнамент, без текста
  и лиц), вместо процедурного SVG: карточки без обложки больше не «пустые».
  Оптимизатор `next/image` ужимает их до ~30 КБ.
- **Никаких технических подписей для клиента** — убраны «Данные обновлены
  N минут назад», статистика на главной, «Проверено N назад» из паспорта:
  клиенту важны источники и доверие, а не метрики синхронизации.
- **Срез ҡусҡар** в углу постера и орнамент — «почерк» продукта
  ([07-design §6](docs/07-design.md)).

### Развёртывание

- Образы собираются **локально на macOS под linux/amd64** (на VPS 4 ГБ RAM
  Next-сборки падают по OOM) и переносятся без registry:
  `docker save | gzip | ssh gvps 'gunzip | docker load'`.
- Стек: `docker-compose.prod.yml` + оверлей `docker-compose.server.yml`
  (порты только на 127.0.0.1 — наружу их отдаёт Caddy с TLS Let's Encrypt).
- **GigaChat требует Russian Trusted Root CA** (НУЦ Минцифры): корень
  кладётся в `infra/certs/` перед сборкой (gitignored, [README](infra/certs/README.md))
  и попадает в образ api через `NODE_EXTRA_CA_CERTS`.
- Синк данных запускается вручную при первом развёртывании:
  `docker exec afisha-api-1 node dist/cli.js ingest:sync`.

## ИИ-гид: модель и стоимость

Двухуровневая маршрутизация: **GigaChat-2** (быстрый разбор запроса: даты,
бюджет, возраст, город) и **GigaChat-2-Pro** (подбор и объяснения по 15
кандидатам из базы). Резервный провайдер — cloud.ru Evolution Foundation
Models (каскад при сбоях/402/429). Без ключей — режим правил.

Стоимость: ≈ **5 ₽ за диалог** (4–5 тыс. токенов, из них 80–90 % — умная
модель; с кэшированием системного промпта — 3–4 ₽). Лимиты (env): 5 ₽ на
диалог, 50 ₽/сутки на пользователя (дальше — режим правил до конца суток),
`AFISHA_AGENT_MAX_STEPS=5`. Rate limit: 60 req/мин на адрес, для Гида —
20 req/мин.

### Контрольный набор запросов ТЗ (разделы 6.5 и 9.2)

98 кейсов / 107 реплик — [`eval/datasets/control.json`](eval/datasets/control.json):
составные запросы, неоднозначности («до 1000 ₽ — на билет или на всех?»),
честный отказ при отсутствии данных, опечатки, промпт-инъекции, статусы,
планирование «выходного дня», многоходовые диалоги. Прогон —
`pnpm --filter @afisha/eval control` (клон демо-БД, фиксированное «сейчас»).
Результат 14.11.2026: **98/98 (100 %)** в режиме правил; 242/242 карточки
в границах запроса, 0 выдуманных событий, 0 ложных отказов, инъекции
отражены 20/20. Против keyword-базлайна: 41/44 против 7/44. Актуальные
цифры — в [eval/reports/control.md](eval/reports/control.md).

## Персональные данные

Минимум, без ФИО, телефонов и e-mail:

- идентификатор устройства (`X-Device-Id`) или Telegram-профиль — только для
  избранного и подписок;
- фильтры подписок — таблица `saved_search`; **срок хранения 90 дней**,
  отписка удаляет строку сразу и безвозвратно;
- история диалога с гидом — 24 часа (TTL);
- журналы обезличены (хеш с `AFISHA_SECRET`), трассировки гида — 90 дней
  в обезличенном виде.

## Открытый REST API: примеры

Интерактивная документация — <https://api.antihype.best/docs> (OpenAPI 3.1),
схема — `GET /openapi.json`. Ответы кэшируются (`ETag`/`If-None-Match` → 304).

```bash
BASE=https://api.antihype.best   # локально: http://localhost:8000

# поиск: сеансы на выходных в Уфе, категория «театр», 6+, 5 штук
curl "$BASE/v1/occurrences?when=weekend&municipality=ufa&categories=theatre&age=6&lang=ru&limit=5"

# карточка-«паспорт» события: источники, provenance полей, история изменений
curl "$BASE/v1/events/<id>"      # <id> — поле event.id из выдачи поиска

# подписка без регистрации (iCal/RSS по сохранённому поиску — тоже)
curl -X POST $BASE/v1/subscriptions -H 'X-Device-Id: demo' -H 'Content-Type: application/json' \
  -d '{"municipality":"ufa","categories":["theatre"]}'

# живость и метрики стека
curl "$BASE/v1/stats"
curl "$BASE/health"
```

Справочники: `/v1/municipalities`, `/v1/categories`, `/v1/venues`.
Конструктор сниппетов виджета — <https://antihype.best/ru/developers>.

## Демо-сценарий (5 минут)

1. **Главная и город** — <https://antihype.best>: окно «Где вам интересно?»,

## Архитектура — кратко

Монорепозиторий pnpm: `apps/api` (Fastify: публичный API, BFF, Admin API,
гид, бот, воркер), `apps/web` и `apps/admin` (Next.js), `apps/widget`
(Web Component), `packages/*` (контракт zod/OpenAPI, i18n, дизайн-токены),
`eval` (оценка гида). PostgreSQL 18 с PostGIS/pgvector/pg_trgm, Valkey,
pg-boss. ИИ-гид — конвейер с формальными инструментами и верификатором,
а не «чат поверх базы». Подробности: [docs/04-architecture.md](docs/04-architecture.md),
модель данных и качество — [docs/06-data.md](docs/06-data.md).

## Известные ограничения

- Покрытие — открытые данные Культура.РФ и Башопера; события, которых нет
  в источниках, не появятся.
- Цены, телефоны и доступность есть в источниках не у всех событий —
  в карточке показывается только подтверждённое.
- Без ключа GigaChat гид в режиме правил: разбор и подбор детерминированные,
  объяснения шаблонные (это же — резервный режим прода).
- Мобильные iOS/Android-приложения — прототипы ([docs/08-mobile.md](docs/08-mobile.md)),
  вне рамок демонстрации.
- Виджет не использует внешние cookies и трекеры; встраивание — только
  на разрешённые домены.
